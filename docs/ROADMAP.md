# Video2URDF 제작 로드맵 (10/27 → 11/5)

마지막 업데이트: 2026-10-27. 계획이 바뀌면 이 문서를 같이 고친다.

## 1. 제작 원칙
1. **처음부터 끝까지 먼저 한 번 이어 붙이기.** 10/30까지는 거칠어도 "영상 → URDF → 시뮬레이션 오버레이"가 한 번에 돌게 만들고, 그다음 정확도를 올린다.
2. **정답지로 먼저, 실제 영상은 나중에.** 모든 알고리즘은 합성 영상(정답 마스크·관절)으로 수치를 확인한 뒤 실제 영상에 적용한다. 이 수치가 그대로 기술 깊이(20점)의 증거가 된다.
3. **단계 사이는 파일로 주고받기.** 캐시, 디버깅, 에이전트 도구, 뷰어가 모두 같은 파일을 쓴다.
4. **외부 의존마다 대안 준비.**
   - 추적: SAM API → 로컬 SAM → 색 스티커
   - 추론: Muse Spark → Glimmer → 규칙 기반
5. **데모가 기능을 결정.** 11/1에 3분 스토리보드를 먼저 쓰고, 화면에 안 나오는 기능은 만들지 않는다. 잘 될 때마다 화면 녹화를 남긴다.

## 2. 데이터 흐름 (실행 폴더 구조)
```
runs/<이름>/
  frames/           프레임 + fps·해상도
  card.json         카드 4꼭짓점 → 평면 호모그래피 H (mm 단위)
  tracks.npz        부품별 마스크  ← 합성 masks.npz와 같은 형식이라 정답으로 바로 채점
  motion.json       부품별 2D 강체 자세 SE(2)(t)
  model.json        ArticulatedModel (src/video2urdf/model.py)
  model.urdf/.xml   + meshes/ (마스크 윤곽을 두께만큼 돌출)
  verify.json       프레임별 실루엣 IoU, 각도 오차, 관절별 점수
  agent_log.json    에이전트 도구 호출 기록
```
`v2u run video.mp4` 하나로 전체를 돌리고, 각 단계는 개별 명령으로 다시 돌릴 수 있게 한다. 정답과 비교하는 명령은 `v2u eval`.

## 4. 단계별 핵심 방법

**추적 (10/28)**
- SAM 3.1은 요청 하나에 개념 하나만 받고, 객체 ID도 요청 안에서만 유지된다.
- 그래서 부품마다 텍스트 프롬프트로 따로 요청한다(예: "red arm"). 어느 요청이 어느 부품인지가 곧 부품 정체성이라 ID 문제가 생기지 않는다.
- 비용은 부품 3개 영상 하나에 약 $0.1.
- 부품 이름과 색은 Muse Spark가 영상을 보고 제안하게 하고, 그걸 SAM 프롬프트로 쓴다. Meta 모델끼리 연결되는 구조라 Meta 활용 점수(25점)의 "기본 연동 이상" 기준을 채우는 포인트.
- 카드는 SAM에 "credit card"로 마스크를 받아 사각형으로 근사하고, 4꼭짓점으로 호모그래피 H를 구한다.

**추정 (10/29), 기술 깊이의 핵심**
1. 카드 호모그래피로 프레임을 정면 시점으로 편다. 그러면 원근 왜곡 없이 단위 mm의 정확한 2D 강체 운동이 된다.
2. 부품별 자세를 구한다. 무늬가 있으면 마스크 안 특징점 추적(KLT)과 RANSAC, 단색이면 마스크 윤곽 정렬(ICP).
   - 합성 부품에 점무늬 텍스처를 넣어 두 방식을 모두 시험한다(생성기 소폭 수정).
3. 부품 쌍의 상대 운동으로 관절 종류를 고른다.
   - 회전: (I−R_t)c = d_t를 최소제곱으로 풀어 중심 c를 구한다.
   - 직선: 이동량의 주성분 방향이 축.
   - 두 모델의 잔차와 BIC를 비교해 종류를 선택한다.
4. 연결 구조: 모든 쌍의 잔차를 비용으로 최소 신장 트리를 만들고, 애매한 부분은 Spark가 판단한다.
5. 관절 한계는 관측된 범위를 그대로 쓴다.

**검증 (10/30)**
- 추정 모델을 영상에 투영해 부품별 IoU와 각도 오차를 계산한다.
- MJCF를 MuJoCo에서 재생한 렌더를 원본 영상과 겹친 장면이 데모의 핵심.

**에이전트 (10/31)**
- Spark의 도구 호출(tool calling)로 루프를 돌린다.
  - `get_scores`
  - `refit_joint(종류, 구간)`
  - `retrack_part(프롬프트)`
  - `set_parent`
  - `emit_and_verify`
- 목표 점수에 도달하거나 반복 횟수 제한에 걸릴 때까지 반복한다.
- Glimmer도 같은 코드로 돌아간다(vLLM `muse_glimmer` 파서).
- 시연용 실패 사례를 일부러 만든다. 예: 작은 회전을 직선으로 오분류, 부모 부품 잘못 지정.

**뷰어 (11/1)**
- Vite + three.js + urdf-loader로 만들고, 실행 폴더를 정적 번들로 불러온다.
- three.js 카메라를 추정한 K, R, t에 맞춰 모델을 영상 위에 정확히 겹친다.
- 타임라인과 관절 슬라이더는 작게 둔다. 대시보드처럼 보이면 금지 규정에 걸린다.
- 예제 3개를 GitHub Pages에 올려 X 게시물 링크로 쓴다.

## 5. 11/2 선택: 로봇팔 장면 + Doctor-lite 추천
- **로봇팔 장면**: "폰으로 찍은 내 서랍을 시뮬레이션 로봇이 연다." 출력 URDF가 바로 쓸모 있다는 걸 보여 줘서 Impact와 Demo, 바이럴에 가장 강하다. MuJoCo Menagerie 로봇 모델(모델별 라이선스 확인 필요)에 정해진 궤적만 주면 하루 안에 가능.
- **URDF Doctor (SO-101)**: Impact에는 좋다. 하지만 SO-101 데이터는 3D 움직임이고 카메라 보정 정보가 없어서 하루 안에 끝내기 위험하다.
- **Doctor-lite**: 우리 측정 결과를 기존 URDF와 비교해 축 부호 반전, 원점 오프셋(mm), 한계 차이를 보고한다. 이미 만든 모델 비교로 반나절이면 된다.
- 그래서 **로봇팔 장면 + Doctor-lite**를 추천하고, SO-101 실데이터는 시간이 남을 때만 한다. 최종 결정은 11/1에 진행 상황을 보고 한다.
